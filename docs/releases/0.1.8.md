## Compatibility

- **CLI, config file, keybindings:** unchanged. Display changes: unknowns render as `?`,
  partial pages and capped lists carry notes, and warnings go to stderr before the TUI
  starts. `keylens probe --queues` prints `?` for an unreadable count, which matters only to
  anyone parsing it.
- **Installer:** now requires `sha256sum` or `shasum` and refuses a release without
  `checksums.txt` (every release since v0.1.0 has one).
- **Library crates (semver-minor at 0.1.x, but breaking):** `KeyMeta.size`, queue counts,
  paused state and stream counts become `Option`. `Conn::read_key` returns `KeyRead`.
  `Conn::key_scanner` returns `Result`. `client_list`/`pubsub_channels` return `Capped<_>`.
  `all_queues` returns `QueueList`. New variants: `KeyValue::Changed`,
  `ConnError::{Unbounded, AuthLost}`, `EventsStatus::Reconnecting`. And the `keylens` lib's
  `worker::{Request, Update}` carry ids. Third-party lenses that issued unbounded reads now
  get `ConnError::Unbounded`. That is intended.
- **Read-only guarantee:** unchanged and strengthened; no write path was added. The guard
  test still passes, and the connection layer now also refuses unbounded read arguments.

## Residual risks

1. **fred CPU spin on accept-then-close outages (pre-existing, upstream).** When a peer
   accepts TCP and closes immediately while a command is buffered (a load balancer with no
   healthy backend, some TLS terminators), fred's reconnect path
   (`reconnect_with_policy` → `Router::retry_buffer`) spins a core until the server
   returns: 12–19 s CPU in a ~21 s outage on **both** 0.1.7 and 0.1.8. A genuine restart
   (connection refused) costs ~0.4 s over a 90 s outage. Reproduce with
   `target/release/examples/bench outage:10`.
2. **Wire transfer is not bounded where Redis cannot bound it:** per-element sizes in any
   page (a 200 × 1 MiB list page still transfers ~200 MiB and peaks ~208 MiB RSS), and the
   count-less `PUBSUB CHANNELS`, `CLIENT LIST`, `XINFO GROUPS/CONSUMERS` and `XPENDING`
   summary. Storage and rendering are bounded; this is documented in `keylens_conn::bounds`.
   `SCAN COUNT` is a hint only.
3. **Error text printed by `main` on a non-interactive failure** (color-eyre) is not
   escape-sanitised. It can include server-supplied error text. The TUI and `probe` output
   are sanitised.
4. **TTL read failure** renders as "no expiry", not "unknown" (rare: a per-command `PTTL`
   denial).
5. **Sentinel with separate credentials** is unsupported: keylens builds fred without
   `sentinel-auth`, so `?sentinelPassword=` is not read (only masked). Userinfo credentials
   authenticate to both the sentinel and the primary.
6. **Binary (non-UTF-8) key names** are counted but cannot be listed or opened.
7. **The scheduled CI** will be disabled again after any future 60-day quiet period. The
   supply-chain job is the one that matters most during such a period.
